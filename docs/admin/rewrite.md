# 管理端重写与验收

## 范围

本次重写的是管理 Web 前端。沿用现有 Laravel V1/V2 API、管理员授权、审计、数据库与业务逻辑；新增源码位于 `admin/`。原 `public/assets/admin` 子模块保留，两个前端可通过查询参数切换。

默认简体中文。菜单分组、地址、列表列和操作方式按旧版管理端恢复，详见 [旧版对照清单](legacy-parity.md)。支持浅色/深色、移动设备导航、功能搜索、分页、空状态、错误反馈、表单校验。页面按需加载；大型 Monaco 编辑器只在使用模板编辑时加载。

## 重要接口差异

- 用户列表余额为元，用户编辑也提交元；订单、支付固定手续费、礼品卡余额为分。
- 套餐 `transfer_enable` 为 GiB，用户和节点额度为字节。
- 套餐/优惠券周期为 `monthly` 等，订单接口保留 `month_price` 等兼容字段。
- 用户列表分页为 `current/pageSize`，单用户流量明细为 `page/pageSize`，礼品卡为 `page/per_page`，审计为 `current/page_size`。
- 编辑节点保留未知协议字段。批量节点更新默认保持原值，只有显式选择才更改开关或机器关联。
- 礼品卡清除无效的空奖励键，不将“未勾选重置套餐”误转为要求领取人已有套餐。拒绝空奖励和非法盲盒权重。活动倍增只作用于数量奖励，不倍乘套餐 ID 或邀请比例；补全禁止套餐条件及旧版 limits.invite_reward_rate 的读取。
- 后台路径变更受常驻路由影响，需要重载应用后生效。

## 验证方法

1. 前端类型检查、契约测试和生产构建。
2. PHP 语法检查与实际 Blade 渲染。
3. Docker 内独立 SQLite、Redis 和测试账号运行完整 Laravel API，网络隔离，避免真实邮件、支付和节点操作。
4. Chromium 验证登录/拒绝普通用户、页面加载、表单保存与回读、手机布局、深色模式和会话过期。
5. 构建开发镜像，备份开发 SQLite，重建开发容器并检查健康状态、新旧入口和静态资源。

隔离浏览器测试命令见 `tests/Admin/run.sh`。所有测试账号使用 `.invalid` 域名，fixture 拒绝非 testing 环境和非 admin-test 数据库。测试目录不得放入真实凭据。

真实支付回调、外部 SMTP 投递、Telegram Webhook、实际节点安装/下发以及第三方上传插件包，不能用隔离环境证明外部服务成功。本次开发环境预览不主动触发这些外部动作，也不改生产环境。

## 开发预览与回滚

开发环境使用 `/<后台路径>?admin_ui=next#/`，原入口仍默认旧版。镜像构建集成前端，不依赖长期开着 Vite 服务。

部署前运行 `scripts/backup-sqlite.sh`，保留原镜像标签。开发环境通过 `docker compose up -d --no-build --pull never --wait` 使用已构建镜像。仅前端回退直接改查询参数为 `admin_ui=legacy`；若需要恢复整个开发镜像，将保留的旧标签重新标记为 `xboard:latest` 后重建开发容器。不要用旧数据库覆盖当前业务数据。

生产发布需另行验收和授权，按本项目 `deploy.md` 导入镜像并以 `--no-build --pull never` 重建。
